# DROP 0006.7 — Fixed-step destruction scheduling and collision rebuild spike control

Status: **complete on the Linux/headless acceptance path**.

Tested code head: `db0fe8310b2d874df3db595b4a617f50504ba9d0`.
Validation: GitHub Actions run 199 (`37112865912`) passed both engine and sandbox jobs.
The documentation commit containing this file is intentionally docs-only and uses `[skip ci]`.

## What this drop was actually fixing

The contact sampler was already scheduled after Avian's fixed physics step in
`FixedPostUpdate`. Moving that sampler again would not have fixed the observed
run-to-run variation.

The real nondeterministic boundary was around it:

```text
authoritative cell/fragment mutation
        ↓
derived collider/body work paced by Update/render-frame retirement
        ↓
fixed physics step sometimes sees a different set of current colliders
        ↓
different contact opportunities
```

DROP 0006.7 makes scripted destruction steps wait for authoritative collision
derived from the current cells/fragments. Render mesh progress is explicitly not
part of that decision.

This is also the remaining collision spike-control work from the original
0006.x sequence: expensive static collision compilation no longer runs
synchronously on the main update path.

## Phase 0 — close the 0006.6 policy questions

### Mean versus median

A median-derived policy was added beside the existing mean-derived policy.
A pure-layer test proves the distinction with a tail-heavy component
distribution: one large component can pull the mean upward while the median
remains at the scale of the typical component.

The real canonical 60-cell re-fracture fixture, however, does **not** distinguish
the two. At all three measured energies, `coherent_mean` and
`coherent_median` produce identical fragment membership.

| energy | per-crack | coherent mean | coherent median |
|---:|---:|---:|---:|
| 1200 | 24 fragments / 8 singletons | 16 / 0 | 16 / 0 |
| 2500 | 32 / 16 | 16 / 0 | 16 / 0 |
| 6000 | 32 / 16 | 16 / 0 | 16 / 0 |

Decision: **do not change the global default**.

`FragmentPartitionPolicy::default()` remains `PerCrackComponent`.
The coherent policies remain available as explicit opt-ins. One real
transaction-fixture family is not enough evidence to change destruction
character globally, and mean versus median has no observed difference on that
fixture.

## Fixed-step authoritative collision readiness

`sim_lab::apply_pending_fixed_step` now gates scripted fixed steps on:

```text
current static collision derived from live world cells
+
current fragment collision derived from native fragment cells
```

through `pending_fixed_step_collision_work`.

It does **not** wait for render mesh uploads.

A slow machine may take more wall-clock time before a scripted step is allowed,
but it must not take a different physics step merely because more or fewer
rendered frames retired.

A hard-budget-withheld fragment is treated as a settled host-policy outcome
rather than an async job that can deadlock scripted stepping.

## Static collision rebuild architecture

### Before

Static collision compilation happened synchronously in
`sync_static_colliders`:

```text
live volume
  → GreedyCollisionCompiler.compile(...)
  → Avian compound collider
```

The host bounded the number of rebuilds per rendered frame, but the CPU compiler
itself still lived on the main schedule.

### After

```text
live volume + revision
      ↓
owned one-volume snapshot
      ↓
bounded async collision job
      ↓
ready result keyed by VolumePos
      ↓
revision/stale validation
      ↓
bounded deterministic backend publication
```

Key properties:

- maximum 8 active static collision worker jobs;
- maximum 8 static collider publications per rendered frame;
- one job slot and one ready-result slot per `VolumePos`;
- repeated edits coalesce instead of creating unbounded duplicate work;
- an edit superseding an in-flight snapshot drops that obsolete job;
- a stale completed result cannot publish;
- ready results publish in deterministic nearest-first order;
- one collision job snapshots one storage volume only;
- collision is derived from cells, never from the render mesh.

The worker contract lives in `engine_destruction::derived_jobs`, with no Bevy
or Avian types in engine crates.

## Fragment collision and motion

Fragment collision compilation was already asynchronous before this section.
0006.7 closes the scheduling/freshness gaps around it:

- render presence is no longer a prerequisite for physics collision readiness;
- fragment collider readiness participates in the scripted fixed-step barrier;
- collision jobs remain keyed by exact `FragmentId` and geometry revision;
- fragment pose/motion does not invalidate geometry-derived collision;
- stale geometry results remain rejected.

When nearby static collision is known to be incomplete, real fragment bodies
temporarily leave the backend rather than simulating through missing collision.
Their authoritative pose and velocity remain in the native `Fragment`; when
collision is current again the body is recreated from that engine-owned state.
This freezes conservatively instead of resetting or silently tunnelling.

## Render meshes

No 0006.7 render-mesh rewrite was necessary.

The existing `MeshScheduler` already provides the architecture this drop
requires:

- requests deduplicated by render section;
- deterministic priority ordering;
- bounded active worker count;
- bounded snapshot bytes;
- stale-result rejection and requeue;
- bounded result count per apply tick;
- bounded upload bytes;
- no ordinary-path mesh compilation on the main schedule.

Changing it merely to make this drop touch "mesh" would have been churn.

## Contact replay determinism

The old stress replay was not a regression oracle. Identical code had produced
different outcomes because fixed physics/contact opportunities depended on
frame-paced derived state.

0006.7 adds a dedicated authoritative verifier and CI gate. The same contact
volley runs three times under Xvfb + Mesa lavapipe, with six checkpoints per
run. Backend poses and wall-clock/frame timing are deliberately excluded; the
authoritative topology, queue outcomes and replay progress must match exactly.

## Deliberately still open

### Windows / real GPU evidence

Linux software Vulkan proves engine behavior, not production GPU frame cost.
Still pending on Windows hardware:

```text
frame interval p50 / p95 / p99 / max
frames over 33.3 ms
GPU-frame response latency
the old 544-fragment ~200–319 ms response observation
```

Lavapipe timings must not be presented as evidence that those costs are solved.

### Fracture index memory

The ~83% index-over-record-payload overhead remains untouched. The cheap
volume-major key rewrite is still blocked on making
`FractureState::digest()` canonical independently of storage order. That should
be an isolated equivalence change before storage layout moves.

### Existing 0006.5 caveats

Still open by contract or as follow-up evidence:

- `prune_against` scans the complete fracture state;
- `forget_space(StaticWorld)` is whole-space by definition;
- the old ~2.2× locality capture residual remains unattributed but under 0.1 ms
  absolute in the recorded environment.

### Fragment-shape policy

The static probe reports eight sliver-shaped pieces, and 0006.6 still has one
real re-fracture fixture family. Shape-aware grouping/minimal-cut work remains a
future modeling question, not something 0006.7 silently tuned.
