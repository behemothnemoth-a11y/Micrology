# DROP 0006.6 — Coherent fragment distribution

The question this drop answers is not whether material fractures. That worked.
It is how a broken volume should turn into coherent native fragments.

Nothing about the damage decision changed. What changed is that grouping is now
a separate, explicit, deterministic layer with a policy, and the accepted
behaviour is one of that policy's settings rather than the only thing the code
can do.

## Phase 1 — what the accepted implementation actually did

A deterministic headless fixture, `fragment_distribution_bench`, over the
existing canonical 60-cell chunk at three contact energies. It runs each case
twice and asserts the two measurements are identical, because a fixture that is
not deterministic cannot be compared to anything.

At 2,500 energy, before this drop:

| quantity | value |
|---|---|
| cells failed | 0 |
| bonds affected | 44 |
| fragments | 32 |
| singletons | 16 |
| mean fragment | 1.88 cells |
| largest fragment | 3 cells, 5.0% of mass |
| largest three | 15.0% of mass |
| occupancy groups | **1** |

Nothing was destroyed and nothing ended up in a large piece: a contact impact
turned one contiguous 60-cell lump into 32 native objects averaging under two
cells.

`occupancy_groups` is the measurement that made the rest of the drop possible.
All 32 pieces' cells taken together form a **single** face-connected group, so
the material was cut apart by cracks and is still touching — it was never
separated in space.

Two measurement details worth keeping:

* `bonds_broken` has to be summed across every surviving fragment's own space.
  After a re-fracture the parent is gone and its records have been remapped to
  the children, so asking the parent's space reports zero broken bonds for a
  break that broke forty-four.
* `crossing_broken_bonds` came back **zero** against 72 inter-fragment faces.
  That is not evidence the boundaries were fake. `FractureState::remap_fragment`
  drops any bond whose endpoints land in different children, because
  fragment-local coordinates are per-fragment and such a bond has nowhere to
  live. **The cracks that justified the split are unrepresentable once the split
  happens.**

That last point is the architectural finding of the drop, and it inverts the
obvious worry about grouping.

## Phase 2 — where the fragmentation came from

```text
impact -> damage + fracture analysis -> failed cells / broken bonds
       -> fracture-aware components -> [one Fragment each] -> native Fragments
```

`fracture_fragment_if` did `components.components.into_iter().map(|c| c.cells)`:
one native object per fracture-aware component. `detach.rs` does the same for
occupancy components on the static path.

Fracture-aware components are strictly finer than occupancy components. Two of
them are separate precisely because *every* face between them is a broken bond —
which is also why **no per-cut strength signal can work here**. Every cut looks
identical by that measure. A signal has to come from somewhere else.

## Phase 3 — the partitioning layer

`engine_destruction::fragment_partition` sits between topology and `Fragment`
creation. It takes `&[Component]` and a policy, and returns groups of cells.

It is deliberately not a topology authority, and the type signature is most of
the argument: it is handed components and nothing else. No `World`, no
`FractureState`, no `FragmentStore`, no residency, no bond gate. It therefore
cannot compute connectivity, cannot consult damage history, and cannot scan
anything global — DROP 0006.5's locality is safe by construction rather than by
care. Specifically it:

* never splits a component, which would invent a boundary where the fracture
  state records no crack;
* never groups material that is not face-adjacent — adjacency is read from the
  cells, and `groups_are_face_connected` is asserted at the call site;
* never erases a crack.

### Grouping is cracking, not welding

When both sides of a broken bond land in one group, the bond record still says
broken. The fracture-aware classifier still sees two components *inside* that
fragment, and a later impact still separates them along the same surface. And
because the bond's endpoints are now in the same fragment, `remap_fragment` can
finally carry it.

So grouping **retains more information than splitting does**. Measured, at 2,500
energy: splitting into 32 fragments retains **0** broken bonds, because every
separating crack is dropped. Grouping into 16 retains **20**.
`a_merged_group_keeps_its_internal_cracks_instead_of_dropping_them` pins both
halves of that.

### The scale is emergent

There is no "make N pieces" anywhere. The threshold is derived from the size
distribution the break itself produced — the mean component size of this break —
and from nothing else. The same policy on a different break yields a different
scale.

The scale is computed in thousandths, following the engine's `_milli`
convention, and this is not cosmetic: 60 cells in 32 components is a mean of 1
under integer division, which no component is smaller than, so every threshold
at or below the mean silently became a no-op. The first implementation had that
bug and the measurement caught it.

Reading it: `coherent_mean` removes every singleton, halves the fragment count,
roughly triples the largest-fragment share and retains 20 cracks that were
previously thrown away. `coherent_twice_mean` collapses everything to one body,
which is too coarse to be a default. `coherent_half_mean` is below any real
component at the finer energies and is a no-op there.

**The shipped default is unchanged — `PerCrackComponent`.** A host opts in. The
default was not switched to `coherent_mean` because that is a destruction
character decision, the brief says character must not change merely to look
better, and the table is the input to that decision rather than a substitute for
it.

every size, the histogram, both checksums. The fixture file grew by the variant
rows and changed in nothing else; the accepted behaviour is not hidden behind a
regenerated golden file.

Twelve new tests. The pure layer: `PerCrackComponent` is a passthrough,
non-touching material is never grouped at any policy, groups are always
face-connected, no cell is lost or duplicated, grouping is invariant under every
rotation and reversal of the input order, an empty component never becomes a
fragment, and an exhausted work budget falls back to the unmerged grouping.
Through the real transaction: grouping changes the fragments but not what broke,
merged groups keep their internal cracks, merged fragments still re-fracture
through the ordinary stack, identity stays unique, and the fixture partitions
identically on repeat runs.

## Budget behaviour

`PartitionLimits` bounds face lookups and merge rounds. Exhaustion returns the
**unmerged** grouping — more fragments, never more destruction — and sets
`budget_exhausted`. This layer cannot destroy anything, because it never decides
what detaches, only how what already detached is grouped. So budget exhaustion
here can only cost coherence, which keeps "inconclusive" and "permission to
destroy" as separate things.

## Costs

Partition work is reported per run: components in, groups out, cells inspected,
faces inspected, candidates considered, merges applied. The adjacency build is
three face lookups per cell (positive axes only, so each face is visited once),
and merging is a union-find over components with a bounded round count.

The stage timing is reported as analysis-and-partition together, around 0.6 to
1.0 ms on this container for a 60-cell chunk — it is *not* isolated partition
time, and no millisecond threshold is asserted anywhere. Temporary allocation is
one cell-to-component map plus an adjacency map, both proportional to the
detached material and to nothing else.

## Remaining pathological cases and limitations

* **`coherent_twice_mean` degenerates to a single fragment** on this fixture. It
  is a useful upper bound for the table, not a usable policy.
* **The scale is a mean**, so it is sensitive to a long tail: one large component
  among many tiny ones raises the threshold and merges more aggressively than a
  median would. A median or a percentile may behave better and is untested.
* **The static path is unchanged.** `fracture_static_if` still routes through
  `cracked_structure_result` and `detach_if`, one fragment per occupancy
  component. That path's over-fragmentation has not been measured, so it has not
  been touched; wiring the same policy through it needs its own baseline first.
* **Only one fixture.** The canonical 60-cell chunk at three energies. The
  demolition building's roof release produces one large fragment already and so
  exercises none of this.
* **Merging is greedy, not optimal.** Each under-scale group joins its largest
  neighbour, iterated. It is deterministic and bounded, not a minimal-cut
  partition, and no claim is made that it is the best grouping of a given break.
* **No shape term.** Aspect ratio and surface-to-volume are measured and
  reported but do not influence grouping, so the policy can produce a coherent
  mass that is a poor shape.
